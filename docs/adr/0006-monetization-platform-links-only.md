# ADR: 収益化はプラットフォームリンク設置のみとし、独自の決済・会員管理は実装しない

> ステータス: Accepted (2026-09-16)
> 根拠: [X (Twitter) 自動通知有料化に伴う更新時通知代案および収益化案の損益見積もり](../records/2026-09-13_twitter-api-notification-and-monetization-estimates.md)

## 背景と問題

X API の有料化に伴い、デイリー集約投稿（[ADR-0005](0005-x-daily-digest-notifications.md)）でも
年間 4,000〜6,000 円程度の API 費用が発生する。この費用を補填し、個人運営の継続性を高める
目的で収益化を検討した。前提要件は「プラン別の機能制御をしない」「法人格なし（個人）」
「固定費ゼロ」「赤字リスクなし」の4点。

自前決済（Stripe Payment Links 等）を組み込む案を検討したが、個人が決済を扱う場合は
特定商取引法に基づき本名・自宅住所・電話番号の公開が原則義務付けられる。回避するには
バーチャルオフィス等の固定費（月数百円〜千円）が発生し、要件の「固定費ゼロ」に反する。

## 決定

- 決済・会員管理は自前実装せず、外部支援プラットフォームへのリンク設置のみで収益化を完結させる。
- 採用するプラットフォームは次の2つ。
  - **OFUSE**（単発支援・月額支援の両方に対応。特定商取引法上の個人情報公開が不要）
  - **GitHub Sponsors**（手数料最安。海外 Simutrans コミュニティとの親和性が高い）
- ポータル側には支援者を識別・管理する仕組み（DB フラグ、Webhook 連携、権限制御等）を設けない。
  支援の有無によって閲覧・投稿機能が変わることはない。
- 実際のリンク URL はこの ADR に記載しない。実装（フロント側のリンク定義）を正とする。

## 検討した代替案と却下理由

- 案A（Stripe Payment Links 等の自前決済）: 特定商取引法により本名・住所等の公開義務が生じ、
  個人運営のリスクが大きいため却下。
- 案B（プラン別に機能を解放する有料会員制）: DB・認可ロジックの改修が必要になり、「追加機能
  なし・固定費ゼロ」の要件に反するため却下。調査記録が示す通り支援者1名で年間 API 費用を
  相殺できるため、機能解放に見合う開発コストをかける動機が薄い。
- 案C（広告掲載、Google AdSense 等）: 調査記録の通り最低支払閾値に達するまで半年以上かかり、
  サイト表示速度・景観への影響に見合わないため却下。

## 影響・トレードオフ

- 支援状況（誰がいくら支援したか）はポータル側では把握できない。感謝表示やバッジ等を出したい
  場合は、各プラットフォームの管理画面を見ながらの手動運用になる。
- 収益はプラットフォームの手数料（OFUSE: 10%、GitHub Sponsors: 0〜6%）が差し引かれる。
- 将来、支援者向け機能（バッジ表示、限定コンテンツ等）を追加したくなった場合は、この ADR を
  覆す必要がある（Webhook 連携や会員 DB 設計が必要になる）。
