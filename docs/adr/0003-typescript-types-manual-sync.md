# ADR: OpenAPI を SSOT とし、TypeScript 型定義は自動生成せず手動で追従させる

> ステータス: Accepted (2025-11-24)
> 由来: `docs/spec/api-contract-typescript-types-spec.md` の決定部分を抽出

## 背景と問題

API ドキュメント（OpenAPI 3.0、`app/OpenApi/`）とフロントエンドの TypeScript 型定義
（`resources/js/types/`）を同期させる必要がある。自動生成ツールを導入する案と、
手動で追従させる案があった。

## 決定

- **OpenAPI 仕様が SSOT**
- **TypeScript 型定義は手動で作成・更新する**（自動生成は導入しない）

| 観点 | 手動管理 | 自動生成 |
| --- | --- | --- |
| 型の精度 | 実装に合わせて調整可能 | スキーマの表現力に制約される |
| 依存関係 | 増えない | 生成ツールの依存が増える |
| IDE 補完 | 確実 | 生成物の型次第 |
| 同期の担保 | **自動検証なし（下記トレードオフ参照）** | ツールが機械的に同期 |

## 検討した代替案と却下理由

- 案A（openapi-typescript 等で自動生成）: 生成ツールへの依存が増え、生成結果の
  カスタマイズ（`ArticleMypageEdit` のような画面別の型分割等）がスキーマの表現力に
  制約されるため却下。

## 影響・トレードオフ

- **この契約を検証する自動テスト・CIは現時点で存在しない**（`package.json` に型生成・
  契約テストの仕組みなし、`.github/workflows/openapi-docs.yml` は OpenAPI JSON の生成と
  lint のみで TypeScript 型との突合はしていない）。同期がずれても検知する仕組みがない。
  この点は本 ADR 単体では解決しない残課題として認識する。
- 命名規則やディレクトリ構成の具体例は実装（`resources/js/types/`）が変化するため
  本 ADR には書かない。現状のパターンは実装ファイル自体を参照する。
- 再検討のトリガー: 型のズレによる実障害が発生した場合、契約テスト（例:
  OpenAPI スキーマと `.d.ts` の構造を比較する簡易テスト）の追加を検討する。
