# ADR: X の公開・更新通知を1日2回の集約投稿へ移行する

> ステータス: Accepted (2026-09-15)
> 根拠: [X (Twitter) 自動通知有料化に伴う更新時通知代案および収益化案の損益見積もり](../records/2026-09-13_twitter-api-notification-and-monetization-estimates.md)

## 背景と問題

記事の公開・更新ごとに X へ通知すると、X API の URL 付き投稿に従量費用が発生する。
更新は特定日に最大 17 件まで集中するため、費用だけでなく、短時間の連続投稿による
タイムライン上のノイズも問題になる。

一方、X 経由の流入はサイトにとって一定の割合を占め、URL を含む投稿は直接の閲覧導線を
維持できる。通知を止めずに投稿回数を抑え、当日中の新規・更新記事を読める形で伝える必要がある。

## 決定

- X の記事公開・更新時の即時投稿を廃止する。
- 毎日 **12:00** と **21:30**（JST）に、前回の成功配信以降の公開・更新記事を1投稿へ集約して
  配信する。対象が0件の場合は投稿しない。
- 1投稿に掲載する記事は最大3件とし、各記事のタイトルと個別 URL を掲載する。
- タイトルは X の重み付き文字数で最大54文字とし、超過分は末尾を `…` に省略する。
  投稿全体は `twitter-text` で280文字以内であることを検証し、必要な場合はタイトルをさらに省略する。
- 4件目以降は `ほかN件` と表示する。超過記事のために投稿を分割しない。
- この ADR の対象は X のみとする。Bluesky、Misskey、Web プッシュの配信方式は別途決定する。
- 収益化・支援サービス・課金者管理は、必要な外部アカウント等を準備した後に別途決定する。

`po` スキーマの本番スナップショットで、2025-09-01以降に公開または更新された公開記事135件を
確認した。タイトルの X 重み付き文字数は中央値26、75パーセンタイル34、90パーセンタイル46であり、
127件（94.1%）が54文字以内だった。54文字の上限は、通常のタイトルをほぼ省略せずに、3件分の
個別 URL と `ほかN件` を280文字内へ収めるための上限とする。

## 検討した代替案と却下理由

- 案A（公開・更新ごとの即時投稿を維持する）: 更新が集中する日に連続投稿となり、URL 付き投稿の
  API 費用もイベント数に比例して増えるため却下。
- 案B（21:30の1日1回だけに集約する）: 夜間のエンゲージメントには適するが、午前・昼の更新通知が
  半日以上遅れる。12時台にも X 経由流入があり、0件時は送信しないため、2枠化の増分コストは
  実際に更新があった枠に限られるため却下。
- 案C（掲載しきれない記事を複数投稿へ分割する）: 投稿回数の抑制という目的に反し、更新集中日の
  タイムライン上のノイズを再発させるため却下。
- 案D（記事 URL を載せず一覧 URL のみを載せる）: 各記事への直接導線を失うため却下。

## 影響・トレードオフ

- 記事公開・更新から通知まで最大で約12時間の遅延が生じる。
- 1枠で4件以上の対象がある場合、4件目以降は X の投稿本文から直接開けない。
- 1日2枠により、更新が両方の時間帯に発生する日は1日1枠より API 費用が増える。ただし、対象0件の
  枠は API を呼び出さないため、投稿数は更新があった半日枠の数に限定される。
- 投稿本文の文字数規則は X の仕様に依存するため、固定長の独自計算ではなく `twitter-text` による
  最終検証を必要とする。
